# Kitchen AI

Photograph your fridge, pantry and spice rack — get meal plans you can actually cook tonight.

Kitchen AI keeps a live inventory of everything in your kitchen and generates daily, weekly and
monthly meal plans **grounded in what you actually have**. Every recipe comes with steps, the exact
ingredients it consumes, photos and a YouTube video. Fully bilingual: English and Arabic with real
RTL mirroring.

Design spec: [`docs/superpowers/specs/2026-07-26-kitchen-ai-design.md`](docs/superpowers/specs/2026-07-26-kitchen-ai-design.md)

---

## What it does

| Capability | Detail |
|---|---|
| Capture inventory | Photo (fridge / pantry / spice rack), barcode, receipt scan, manual entry |
| Live inventory | Quantities, storage locations, expiry tracking, auto-deduct when you cook |
| Meal plans | Daily · weekly · monthly, strict for daily, shopping-list-backed for longer horizons |
| Recipes | Steps, used ingredients, photos, YouTube videos |
| Households | Shared inventory, multiple members, invite codes |
| Bilingual | English + Arabic, full RTL, AI writes recipes in your selected language |

## Repo layout

```
apps/
  api/          NestJS + Drizzle + PostgreSQL (pgvector)
  web/          Next.js (Phase 1)
  mobile/       Expo / React Native (Phase 1)
packages/
  contracts/    Zod schemas + the single route registry — the frozen interface
  api-client/   Typed fetch client derived from contracts
  i18n/         Typed en/ar message catalogs, RTL + numeral formatting
  config/       Shared tsconfig / eslint / prettier presets
docs/superpowers/specs/   Design spec
```

`packages/contracts` is the contract between every other package. The API validates against it, the
client is typed from it, and the web/mobile mocks are generated from it — so the client and server
can never drift apart.

## Prerequisites

- Node.js >= 20 (developed on 26.5)
- pnpm 10 — `npm i -g pnpm@10`
- Docker (for PostgreSQL, Redis and MinIO)

## Getting started

```bash
# 1. Install dependencies
pnpm install

# 2. Configure
cp .env.example .env
#   AI_MOCK=true is the default, so no OpenAI key is needed to run locally.
#   Set OPENAI_API_KEY and YOUTUBE_API_KEY when you want live AI + videos.

# 3. Start infrastructure (PostgreSQL 17 + pgvector, Redis, MinIO)
pnpm infra:up

# 4. Create and apply the schema
pnpm db:generate
pnpm db:migrate

# 5. Load the bilingual ingredient catalog (~500 items)
pnpm db:seed

# 6. Run
pnpm dev
```

Health check: `curl http://localhost:3333/health`

## Conventions

**Never edit `packages/contracts` from an app.** Contract changes are coordinated centrally,
because both sides of every request are generated from it.

**`packages/i18n` is append-only per namespace.** Each workstream owns its own namespace inside
`en.ts` / `ar.ts` so parallel work does not collide. Adding a key to `en` without adding it to `ar`
is a build error by design.

**No physical-direction styles.** ESLint rejects `ml-*`, `pl-*`, `left-*`, `text-left`,
`marginLeft`, etc. Use logical properties (`ms-*`, `ps-*`, `start-*`, `text-start`,
`marginStart`) so Arabic mirrors correctly without a second stylesheet.

**Inventory is an event ledger.** `inventory_items.quantity` is materialized state derived from the
append-only `inventory_events` table. That is what makes offline replay and concurrent household
edits safe.

**YouTube video ids are never generated by the model.** They always come from the YouTube Data API
and are cached per recipe.

## Meal plan generation

Three deliberate stages (spec §5):

1. **Stage A — deterministic SQL.** Build the exact pantry snapshot, including staples.
2. **Stage B — LLM.** Generate candidate recipes and a plan as structured output.
3. **Stage C — deterministic validation.** Re-check every ingredient against the pantry.

Daily plans that fail Stage C are regenerated (max 2 retries). Weekly and monthly plans convert
shortfalls into shopping list items instead of failing.
